# Primitive DB

Примитивная база данных на Python с интерфейсом командной строки.

## Технологии

- Python 3.12+
- uv — управление проектом и зависимостями
- prompt — пользовательский ввод
- shlex — разбор команд
- JSON — хранение метаданных и данных таблиц
- PrettyTable — форматированный вывод записей
- Ruff — проверка и форматирование кода

## Управление таблицами

База данных поддерживает следующие команды:

| Команда | Описание |
|---|---|
| `create_table <имя> <столбец:тип> ...` | Создать таблицу |
| `list_tables` | Показать список всех таблиц |
| `drop_table <имя>` | Удалить таблицу |
| `help` | Показать справочную информацию |
| `exit` | Завершить работу программы |

### Создание таблицы

Для создания таблицы укажите её имя и столбцы с типами данных:

```text
create_table users name:str age:int active:bool
```

Столбец `ID:int` добавляется автоматически в начало структуры таблицы.

Поддерживаемые типы данных:

- `int` — целое число;
- `str` — строка;
- `bool` — логическое значение (`true` или `false`).

### Просмотр таблиц

Для просмотра списка существующих таблиц используйте:

```text
list_tables
```

### Удаление таблицы

Для удаления таблицы укажите её имя:

```text
drop_table users
```

### Пример использования

```text
Введите команду: create_table users name:str age:int
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int

Введите команду: list_tables
- users

Введите команду: drop_table users
Таблица "users" успешно удалена.

Введите команду: list_tables
Таблиц пока нет.

Введите команду: exit
Выход из программы.
```

## Хранение метаданных

Информация об именах таблиц и структуре их столбцов сохраняется в JSON-файле `db_meta.json`.

Если файл метаданных отсутствует, база данных начинает работу с пустым словарём.

## CRUD-операции

База данных поддерживает полный набор операций для работы с записями (CRUD).

### Добавление записи (INSERT)

Для добавления записи укажите имя таблицы и значения для её столбцов:

```text
insert into users values ("Sergei", 28, true)
```

ID генерируется автоматически. Пользователь передаёт значения только для остальных столбцов.

Количество значений и их типы должны соответствовать структуре таблицы.

### Чтение записей (SELECT)

Получить все записи:

```text
select from users
```

Получить записи по условию:

```text
select from users where age = 28
```

Результаты выводятся в виде таблицы с помощью PrettyTable.

### Обновление записи (UPDATE)

Для изменения значений используйте команду `update` с указанием таблицы, новых значений и условия:

```text
update users set age = 29 where name = "Sergei"
```

Условие `WHERE` определяет, какие записи необходимо обновить.

### Удаление записи (DELETE)

Для удаления записей укажите условие:

```text
delete from users where ID = 1
```

Условие `WHERE` обязательно.

### Информация о таблице

Команда `info` выводит информацию о таблице:

```text
info users
```

Отображаются название таблицы, её столбцы и количество записей.

## Хранение данных

Данные каждой таблицы хранятся в отдельном JSON-файле в директории `data/`.

Например, данные таблицы `users` сохраняются в:

```text
data/users.json
```

При добавлении, обновлении и удалении записей соответствующий JSON-файл обновляется.

## Декораторы и замыкания

Для повышения надёжности и удобства работы Primitive DB использует декораторы и замыкания.

### Обработка ошибок

Декоратор `handle_db_errors` централизует обработку ошибок при выполнении операций с базой данных.

Он обрабатывает следующие исключения:

- `FileNotFoundError` — файл данных не найден;
- `KeyError` — обращение к отсутствующему ключу;
- `ValueError` — ошибка валидации данных;
- другие непредвиденные исключения.

При возникновении ошибки выводится соответствующее сообщение, а выполнение операции прекращается.

### Подтверждение опасных действий

Декоратор `confirm_action(action_name)` запрашивает подтверждение перед выполнением опасных операций.

Он применяется к функциям удаления таблицы и записей.

Пример запроса:

```text
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]:
```

Для выполнения операции необходимо ввести `y`. При любом другом ответе операция отменяется.

### Измерение времени выполнения

Декоратор `log_time` измеряет время выполнения функций `insert` и `select` с помощью `time.monotonic()`.

Результат выводится в консоль в формате:

```text
Функция insert выполнилась за 0.001 секунд
```

### Кэширование результатов

Функция `create_cacher()` реализует кэширование с помощью замыкания.

Внутренняя функция `cache_result(key, value_func)` хранит результаты запросов в словаре и возвращает сохранённый результат при повторном обращении с тем же ключом.

Механизм интегрирован в операцию `select`. Ключ кэша учитывает содержимое таблицы и условия запроса, поэтому при изменении данных формируется новый ключ и возвращается актуальный результат.
